# Unit 1.3 — Make 10

- **Unit:** 1.3
- **Domain:** D1 — Number Sense & Composition
- **Purpose:** develop "bridge through ten" as a flexible mental-addition strategy built
  entirely from already-secure skills (part/whole, bonds, complements to 10) — the
  capstone unit of Foundation Release 1's number-sense strand.
- **Prerequisites:** Unit 1.2 complete (fluent complements to 10), Unit 1.1 (bond
  fluency, missing-part reasoning).
- **Unlocks:** Unit 2.1 (Tens and Ones — "10 ones make a ten" is now a familiar quantity,
  not a new idea); addition/subtraction strategies generally (D3).
- **Primary patterns:** Make a Benchmark, Part/Whole.
- **Primary representations:** `NumberBond` (for the 5=3+2-style split) →
  `EquationWorkspace` (for the full given→work→result flow) → `TransformationChain` (for
  the reveal that all forms share one value).
- **Lesson count:** 7 instructional lessons (+ 1 unit mastery check).

> **Sequencing note (P2 finding — see `README.md` §"P2 Prerequisite Findings"):** the
> natural "transfer to bigger numbers" example for Make 10 (e.g., `27 + 5`) requires
> decomposing a two-digit number by place value, which is Unit 2.1 — taught *after* this
> unit. This unit's transfer lesson (1.3.7) therefore stays within single-digit sums; the
> two-digit extension is deferred to a short Connection lesson recommended for
> Foundation Release 2, placed immediately after Unit 2.1.

---

### 1.3.1 — Bridging Through Ten: 7 + 5
- **Type / Difficulty:** Discovery · Entry/Developing
- **Teaching goal:** add two numbers whose sum crosses 10 by breaking one addend to
  complete a ten first, then adding what's left.
- **Student question:** "Can you turn this into a ten first, and then finish?"
- **Prerequisites:** 1.2.3 (complements to 10), 1.1.4 (missing part).
- **New idea:** the full bridge-through-ten sequence, worked for the first time,
  end-to-end.
- **Reuses:** complements to 10 (1.2.3), bond notation (1.1), composing (0.2.3).
- **Reasoning pattern(s):** Make a Benchmark, Part/Whole.
- **Representation:** `NumberBond` (5 = 3 + 2) → `EquationWorkspace` (the full flow) →
  `TransformationChain` (all forms, tagged "same value").
- **Vocabulary:** bridge, benchmark, break apart.
- **SETUP:** the problem `7 + 5` is presented, unsolved.
- **SEE:** 7 needs 3 to reach 10 — the benchmark relationship (1.2.3) noticed in this
  specific problem.
- **BREAK:** split the *other* addend, 5, into the piece that completes the ten and
  what's left: `5 = 3 + 2`.
- **BUILD:** `7 + 3 = 10` — the benchmark is reached.
- **TRANSFORM:** `10 + 2 = 12` — same value as the original `7 + 5`, now in a friendlier
  form.
- **CHECK:** `5 + 7 = 12` (commutativity) confirms the result independently.
- **Primary example:** `7 + 5 = 12`.
- **Second example:** (worked together, same structure) `7 + 4 = 11`.
- **Transfer example:** `7 + 6` — same "7 needs 3" starting fact, new second addend.
- **Misconception:** correctly finds `5 = 3 + 2` but then adds `7 + 2` first instead of
  `7 + 3`, breaking the ten-completing purpose of the split. *Why:* loses track of which
  piece of the split addend was meant to complete the ten — flagged in
  `MISCONCEPTION_MAP.md` as "Make-10 decomposition errors."
- **Teacher response:** "Which piece did we split off to finish the ten? Let's add that
  piece first."
- **Check strategy:** commutativity (`5 + 7 = 12`).
- **Mastery evidence:** correctly executes the full bridge for `7 + 5` and explains each
  stage aloud, unprompted.
- **Unlocks:** 1.3.2.
- **Visual:** `NumberBond`, `EquationWorkspace`, `TransformationChain`.
- **Format:** Both. **Presenter:** Recommended (this is the release's flagship worked
  example — see also the `L_75` reference lesson already accepted in Baseline E).

### 1.3.2 — Bridging Through Ten: 8 + 6
- **Type / Difficulty:** Strategy · Developing
- **Teaching goal:** apply the same bridge-through-ten structure to a second, different
  pair — confirming the strategy generalizes, not a one-off trick for `7 + 5`.
- **Student question:** "Does the same idea work here too?"
- **Prerequisites:** 1.3.1.
- **New idea:** none new conceptually — deliberate immediate repetition with new numbers,
  per P2.13's explicit example progression (7+5, then 8+6, then 9+7).
- **Reuses:** 1.3.1's full sequence.
- **Reasoning pattern(s):** Make a Benchmark, Part/Whole.
- **Representation:** `NumberBond` → `EquationWorkspace` → `TransformationChain`.
- **Vocabulary:** (reinforce bridge, benchmark).
- **SETUP:** `8 + 6`, unsolved.
- **SEE:** 8 needs 2 to reach 10.
- **BREAK:** `6 = 2 + 4`.
- **BUILD:** `8 + 2 = 10`.
- **TRANSFORM:** `10 + 4 = 14`.
- **CHECK:** `6 + 8 = 14`.
- **Primary example:** `8 + 6 = 14`.
- **Second example:** `8 + 5 = 13`.
- **Transfer example:** `8 + 7`.
- **Misconception:** splits the *first* addend (8) instead of the one needed to complete
  it (should split 6, since 8 is the one closer to already being "the benchmark base").
  *Why:* inconsistent rule for which number to split — this lesson's second worked
  example is chosen specifically to force the learner to re-identify "which number needs
  completing" rather than pattern-matching position from 1.3.1.
- **Teacher response:** "Which number is already closer to a ten? Which one are we
  splitting?"
- **Check strategy:** commutativity.
- **Mastery evidence:** correctly executes the bridge for `8 + 6` with correct
  identification of which addend to split.
- **Unlocks:** 1.3.3.
- **Visual:** `NumberBond`, `EquationWorkspace`, `TransformationChain`.
- **Format:** Both. **Presenter:** Optional.

### 1.3.3 — Bridging Through Ten: 9 + 7
- **Type / Difficulty:** Strategy · Developing/Secure
- **Teaching goal:** apply the bridge to a case where the benchmark gap is smallest (9
  needs only 1) — the easiest gap size, deliberately sequenced last so the two harder
  gap sizes (3, 2) are secure first.
- **Student question:** "How small is the piece we need this time?"
- **Prerequisites:** 1.3.1–1.3.2.
- **New idea:** none new — completes the three-example arc from P2.13.
- **Reuses:** the full bridge sequence.
- **Reasoning pattern(s):** Make a Benchmark, Part/Whole.
- **Representation:** `NumberBond` → `EquationWorkspace` → `TransformationChain`.
- **Vocabulary:** (reinforce).
- **SETUP:** `9 + 7`, unsolved.
- **SEE:** 9 needs only 1 to reach 10.
- **BREAK:** `7 = 1 + 6`.
- **BUILD:** `9 + 1 = 10`.
- **TRANSFORM:** `10 + 6 = 16`.
- **CHECK:** `7 + 9 = 16`.
- **Primary example:** `9 + 7 = 16`.
- **Second example:** `9 + 4 = 13`.
- **Transfer example:** `9 + 8`.
- **Misconception:** because the gap is so small (1), skips explicitly stating the split
  and just "counts on by feel," which breaks down on slightly harder numbers later.
  *Why:* the easy gap invites shortcutting the reasoning structure — the lesson
  explicitly requires stating the split (`7 = 1 + 6`) even though it's tempting to skip.
- **Teacher response:** "Even though it's a small jump, can you still show me the split?"
- **Check strategy:** commutativity.
- **Mastery evidence:** correctly executes and *explains* the full bridge for `9 + 7`,
  not just an intuited answer.
- **Unlocks:** 1.3.4.
- **Visual:** `NumberBond`, `EquationWorkspace`, `TransformationChain`.
- **Format:** Both. **Presenter:** Optional.

### 1.3.4 — Make 10 to Subtract
- **Type / Difficulty:** Strategy · Secure
- **Teaching goal:** the bridge-through-ten idea works in reverse for subtraction —
  break the number being subtracted so the first stop is exactly at 10 (or down from it).
- **Student question:** "Can we get to a friendly ten on the way to the answer?"
- **Prerequisites:** 1.3.1–1.3.3 (addition bridge secure).
- **New idea:** applying the same benchmark-bridging structure to subtraction.
- **Reuses:** complements to 10, part/whole (missing-part framing applies directly here).
- **Reasoning pattern(s):** Make a Benchmark, Inverse Operations.
- **Representation:** `NumberBond` → `EquationWorkspace`.
- **Vocabulary:** (reinforce bridge, in the subtraction direction).
- **SETUP:** `13 - 5`, unsolved.
- **SEE:** 13 is close to 10 — subtracting down to 10 first might help.
- **BREAK:** `5 = 3 + 2` (split so the first 3 brings 13 down to 10).
- **BUILD:** `13 - 3 = 10`.
- **TRANSFORM:** `10 - 2 = 8` — same value as `13 - 5`, reached via the ten.
- **CHECK:** `8 + 5 = 13` (inverse operation).
- **Primary example:** `13 - 5 = 8`.
- **Second example:** `14 - 6 = 8`.
- **Transfer example:** `12 - 7`.
- **Misconception:** splits the number being subtracted the wrong way (e.g., for
  `13 - 5`, uses `5 = 2 + 3` but subtracts the 2 first, overshooting past 10 to 11 instead
  of landing exactly on it). *Why:* hasn't yet identified which piece lands exactly on
  the benchmark before splitting — mirrors the addition-direction error from 1.3.1's
  misconception, now in reverse.
- **Teacher response:** "Which piece gets us exactly to 10 — not past it?"
- **Check strategy:** inverse operation (add back to confirm).
- **Mastery evidence:** correctly executes the subtraction bridge for 2 problems.
- **Unlocks:** 1.3.5.
- **Visual:** `NumberBond`, `EquationWorkspace`.
- **Format:** Both. **Presenter:** Optional.

### 1.3.5 — Choosing to Make Ten
- **Type / Difficulty:** Connection · Secure/Transfer
- **Teaching goal:** recognize *when* Make 10 is the efficient choice versus when a
  problem is already easy enough that bridging adds unnecessary steps.
- **Student question:** "Is making a ten actually the fastest way here, or is there an
  easier path?"
- **Prerequisites:** 1.3.1–1.3.4.
- **New idea:** strategy selection — the first explicit "is this strategy worth using
  here?" lesson in the curriculum (a direct instance of `CURRICULUM_ARCHITECTURE.md`
  §9's rules for introducing/comparing/delaying/rejecting a strategy).
- **Reuses:** the full Make 10 sequence; 1.2.5 (choosing between benchmarks).
- **Reasoning pattern(s):** Make a Benchmark.
- **Representation:** `EquationWorkspace` (side-by-side comparison of two approaches).
- **Vocabulary:** efficient, worth it.
- **SETUP:** two problems shown together: `9 + 1` (already exactly 10) and `9 + 6`
  (genuinely needs bridging).
- **SEE:** "Does the first problem need a bridge at all?"
- **BREAK:** notice `9 + 1` is already a complete benchmark fact — no split needed.
- **BUILD:** solve `9 + 1` directly; solve `9 + 6` with the full bridge.
- **TRANSFORM:** two different-looking problems, handled with the *appropriately sized*
  amount of strategy — same underlying number sense, applied proportionally to the
  problem's actual demand.
- **CHECK:** both answers confirmed by commutativity.
- **Primary example:** `9 + 1` (no bridge needed) vs. `9 + 6` (bridge needed).
- **Second example:** `10 + 3` (no bridge needed) vs. `8 + 5` (bridge needed).
- **Transfer example:** a set of 4 mixed problems; the learner sorts them into "needs a
  bridge" and "doesn't" before solving any.
- **Misconception:** applies the full bridge procedure even to already-easy facts (e.g.,
  splits `1` into pieces to add to `9+1`), because "that's what we've been doing." *Why:*
  over-applying a recently learned procedure without checking if it's needed — this
  lesson exists specifically to counter that tendency.
- **Teacher response:** "Do you need to break anything apart here, or is it already
  friendly?"
- **Check strategy:** commutativity; mental reasonableness.
- **Mastery evidence:** correctly sorts 4 mixed problems by whether they need a bridge,
  and solves each appropriately.
- **Unlocks:** 1.3.6.
- **Visual:** `EquationWorkspace`.
- **Format:** Both. **Presenter:** Optional.

### 1.3.6 — Fixing a Broken Bridge
- **Type / Difficulty:** Error Analysis · Secure
- **Teaching goal:** diagnose and correct a shown Make-10 error, rather than only
  producing correct bridges from scratch.
- **Student question:** "Someone tried this and got it wrong — what happened?"
- **Prerequisites:** 1.3.1–1.3.5.
- **New idea:** none new procedurally — this lesson exercises the misconception model
  (`CURRICULUM_ARCHITECTURE.md` §11) directly on the learner's own emerging skill.
- **Reuses:** the full bridge sequence.
- **Reasoning pattern(s):** Make a Benchmark, Part/Whole.
- **Representation:** `NumberBond` / `EquationWorkspace`, shown with an error already
  present.
- **Vocabulary:** mistake, fix, why.
- **SETUP:** a worked (incorrect) solution to `6 + 8` is shown: "`8 = 4 + 4`, so
  `6 + 4 = 10`, `10 + 4 = 14`" — arithmetically the *answer* (14) is accidentally right,
  but the *split* doesn't complete a ten correctly from 6's side (6 needs 4, which this
  split does supply — so this specific instance is actually valid; use the deliberately
  broken version below instead for the primary example).
- **SEE:** "Let's look at this worked solution together before deciding if it's right."
- **BREAK:** re-derive independently what number 6 (or whichever addend anchors the
  bridge) actually needs to reach 10.
- **BUILD:** compare the independent split to the one shown.
- **TRANSFORM:** the broken attempt, repaired into a correct bridge — same problem, a
  corrected form.
- **CHECK:** commutativity confirms the corrected answer.
- **Primary example (deliberately broken):** `6 + 8` solved as "`8 = 2 + 6`, so
  `6 + 2 = 8`" (stops at 8, not 10 — the split piece doesn't actually complete a
  benchmark) — diagnose that the split was aimed at the wrong target.
- **Second example (deliberately broken):** `7 + 5` solved as "`5 = 3 + 2`, so
  `7 + 2 = 9`, `9 + 3 = 12`" (right final answer, wrong order — the ten-completing piece
  was added second, not first) — diagnose that the *order* of the split pieces matters
  for the strategy to do its job, even though the total still came out right here.
- **Transfer example:** a new broken bridge the learner has not seen, for `8 + 4`.
- **Misconception (the one being diagnosed):** splitting toward the wrong target number,
  or adding the split pieces in the wrong order — both previously seen in 1.3.1/1.3.2.
- **Teacher response:** "What number were we actually trying to reach with the first
  step? Did this split get us there?"
- **Check strategy:** commutativity; inverse operation.
- **Mastery evidence:** correctly identifies what's wrong in at least 2 of 2 shown broken
  bridges and produces a corrected version.
- **Unlocks:** 1.3.7.
- **Visual:** `NumberBond`, `EquationWorkspace`.
- **Format:** Both. **Presenter:** Optional.

### 1.3.7 — Make 10 With a New Pair: 6 + 9
- **Type / Difficulty:** Strategy · Transfer
- **Teaching goal:** apply the full Make 10 strategy independently to a pair not
  explicitly drilled in this unit, confirming transfer within the single-digit range.
- **Student question:** "You haven't practiced this exact pair yet — can you still do
  it?"
- **Prerequisites:** 1.3.1–1.3.6.
- **New idea:** none — this is the unit's transfer checkpoint, immediately before the
  mastery check.
- **Reuses:** the entire unit.
- **Reasoning pattern(s):** Make a Benchmark, Part/Whole.
- **Representation:** `NumberBond` → `EquationWorkspace` → `TransformationChain`.
- **Vocabulary:** (none new).
- **SETUP:** `6 + 9`, unsolved, presented without a worked model first.
- **SEE:** which addend is closer to 10? (9, needing 1.)
- **BREAK:** `6 = 1 + 5`.
- **BUILD:** `9 + 1 = 10`.
- **TRANSFORM:** `10 + 5 = 15`.
- **CHECK:** `6 + 9 = 15` (commutativity, using the original order).
- **Primary example:** `6 + 9 = 15`.
- **Second example:** `4 + 8 = 12`.
- **Transfer example:** none beyond this — this lesson *is* the unit's transfer example
  (per the sequencing note above, the two-digit extension is deferred to Foundation
  Release 2, after Unit 2.1).
- **Misconception:** reverts to counting all on fingers from 1 instead of applying the
  bridge, when working independently without a modeled example first. *Why:* transfer
  without a worked model is genuinely harder — if this persists for multiple learners, it
  is evidence the unit needs one more worked example before this transfer lesson, not
  evidence the learner has failed.
- **Teacher response:** "What's the first question we always ask — which number is
  closer to a ten?"
- **Check strategy:** commutativity.
- **Mastery evidence:** independently and correctly executes the full bridge for `6 + 9`
  without a worked model shown first.
- **Unlocks:** the Unit 1.3 Mastery Check; Unit 2.1 (Tens and Ones) — and, per the
  sequencing note, the deferred two-digit Make-10 Connection lesson recommended for
  Foundation Release 2.
- **Visual:** `NumberBond`, `EquationWorkspace`, `TransformationChain`.
- **Format:** Both. **Presenter:** Recommended (unit capstone).
