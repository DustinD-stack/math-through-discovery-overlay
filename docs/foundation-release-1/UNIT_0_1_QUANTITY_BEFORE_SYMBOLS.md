# Unit 0.1 — Quantity Before Symbols

- **Unit:** 0.1
- **Domain:** D0 — Pre-Number Foundations
- **Purpose:** establish that a number names *how many*, independent of arrangement, and
  build the perceptual/comparative tools (subitizing, matching, counting) a learner
  needs before any symbol work.
- **Prerequisites:** none — entry unit of the entire curriculum.
- **Unlocks:** Unit 0.2 (Parts, Wholes & Number Location); indirectly, all of D1.
- **Primary patterns:** Unitize, Part/Whole (informal only — formal treatment is Unit 0.2).
- **Primary representations:** physical objects, dots/counters, informal pairing/matching.
  No design-system component is used in this unit — see `README.md` visual-gap note.
- **Lesson count:** 8 instructional lessons (+ 1 unit mastery check, see `MASTERY_CHECKS.md`).

> **Refinement note (P2):** P1's placeholder list for this unit included "Parts Inside a
> Whole," "Break a Quantity Apart," and "Put Quantities Back Together." Detailed
> blueprinting moved that content to Unit 0.2, alongside compose/decompose/part/whole,
> per this milestone's explicit brief (P2.4/P2.5). Unit 0.1 keeps its original *purpose*
> (P1 §14) unchanged — this is a lesson-placement refinement, not a prerequisite
> correction; see `README.md` §"P2 Refinement Notes."

### 0.1.1 — How Many?
- **Type / Difficulty:** Discovery · Entry
- **Teaching goal:** counting a group accurately answers "how many," and the *last*
  count word said names the size of the whole group (cardinality).
- **Student question:** "How many are there?"
- **Prerequisites:** none.
- **New idea:** cardinality — the last number counted is the answer, not just the last
  object touched.
- **Reuses:** —
- **Reasoning pattern(s):** Unitize (each object = one count).
- **Representation:** Object → Picture (loose counters, then dots on a card).
- **Vocabulary:** how many, count, in all.
- **SETUP:** a small group of objects (4–6) is shown, unlabeled.
- **SEE:** "What do we want to know? How many are here?"
- **BREAK:** touch and count each object once, in any order.
- **BUILD:** the last word said is announced as the group's total.
- **TRANSFORM:** count the *same* group again in a different order — same total.
- **CHECK:** recount once more; does it still come out the same?
- **Primary example:** 5 counters in a loose pile.
- **Second example:** 6 counters in a row.
- **Transfer example:** 7 objects the learner has not counted before (classroom items).
- **Misconception:** recounts and gets a different number each time. *Why:* skips or
  double-counts objects — one-to-one correspondence is not yet secure, not a counting-
  sequence problem.
- **Teacher response:** "Can you touch each one as you say its number, just once?"
- **Check strategy:** recount / alternate representation (line the objects up, recount).
- **Mastery evidence:** counts a group of 5–7 objects correctly twice in a row, in a
  different order each time.
- **Unlocks:** 0.1.2 (subitizing small groups builds on secure counting as a backstop).
- **Visual:** physical objects / dots — no MTD component.
- **Format:** Both. **Presenter:** Recommended (hands manipulating real objects reads
  best with a presenter on camera).

### 0.1.2 — Groups I Can See at a Glance
- **Type / Difficulty:** Discovery · Entry
- **Teaching goal:** small groups (up to 5) can be recognized instantly, without
  counting one-by-one (subitizing).
- **Student question:** "How do you know without counting?"
- **Prerequisites:** 0.1.1.
- **New idea:** subitizing — instant recognition of small quantities from their pattern.
- **Reuses:** counting as the fallback/verification method.
- **Reasoning pattern(s):** Unitize.
- **Representation:** Picture — dot patterns (dice-like arrangements), flashed briefly.
- **Vocabulary:** at a glance, pattern, without counting.
- **SETUP:** a dot card is shown for ~2 seconds, then hidden.
- **SEE:** "How many did you see? How do you know?"
- **BREAK:** compare the seen pattern to a known small pattern (e.g., "like dice").
- **BUILD:** name the quantity from the pattern, not a count.
- **TRANSFORM:** the same quantity shown in an unfamiliar arrangement — still recognized
  (or counted as backup) as the same amount.
- **CHECK:** flip the card back over and count to confirm.
- **Primary example:** a 4-dot square pattern.
- **Second example:** a 3-dot triangle pattern.
- **Transfer example:** a scattered (non-dice) 5-dot arrangement.
- **Misconception:** guesses a number unrelated to the pattern shown. *Why:* treating the
  flash as a memory game rather than looking for structure in the arrangement.
- **Teacher response:** "What did the dots look like? Was it more like 3 or more like 5?"
- **Check strategy:** alternate representation (count after the flash to confirm).
- **Mastery evidence:** correctly names groups of 3–5 from a brief flash on at least 4 of
  5 tries.
- **Unlocks:** 0.1.7 (counting on from a recognized group).
- **Visual:** dot cards — no MTD component.
- **Format:** Both. **Presenter:** Optional.

### 0.1.3 — Same Amount, Different Look
- **Type / Difficulty:** Discovery · Entry/Developing
- **Teaching goal:** rearranging a group of objects does not change how many there are
  (conservation of number) — the first appearance of **SAME VALUE. DIFFERENT FORM.**
- **Student question:** "Did the amount change when I moved them?"
- **Prerequisites:** 0.1.1.
- **New idea:** conservation of quantity under rearrangement.
- **Reuses:** counting to verify.
- **Reasoning pattern(s):** Equivalence (earliest, fully informal instance).
- **Representation:** Object → Picture.
- **Vocabulary:** same amount, moved, spread out, bunched up.
- **SETUP:** 6 counters in a tight cluster; count them together.
- **SEE:** "We counted 6. Watch what I do next."
- **BREAK:** spread the same 6 counters into a long row, in view of the learner.
- **BUILD:** ask for a prediction before recounting: "How many now?"
- **TRANSFORM:** same quantity → different arrangement (this unit's version of
  TRANSFORM — no symbolic step exists yet, and none is invented).
- **CHECK:** recount the spread-out row; it still totals 6.
- **Primary example:** 6 counters, cluster → row.
- **Second example:** 8 counters, row → circle.
- **Transfer example:** a group the learner rearranges themselves, then predicts before
  recounting.
- **Misconception:** insists the spread-out row "has more" because it takes up more
  space. *Why:* judging quantity by length/area instead of count — a normal
  developmental stage, not carelessness.
- **Teacher response:** "Let's count them together and find out — were any added or
  taken away?"
- **Check strategy:** recount / mental reasonableness ("did anyone add or remove one?").
- **Mastery evidence:** correctly predicts the count stays the same before recounting,
  across at least two different rearrangements.
- **Unlocks:** 0.2.2 (decomposition is itself a rearrangement that preserves quantity).
- **Visual:** physical objects — no MTD component.
- **Format:** Both. **Presenter:** Recommended.

### 0.1.4 — Matching to Compare
- **Type / Difficulty:** Strategy · Developing
- **Teaching goal:** two groups can be compared by pairing them up one-to-one, without
  needing to count either group first.
- **Student question:** "Which group has more — can you tell without counting?"
- **Prerequisites:** 0.1.1.
- **New idea:** one-to-one correspondence used as a *comparison tool*, not just a
  counting tool.
- **Reuses:** one-to-one correspondence (0.1.1).
- **Reasoning pattern(s):** Part/Whole (comparison as a precursor).
- **Representation:** Object → Picture (two rows, lined up under each other).
- **Vocabulary:** pair up, left over, none left over.
- **SETUP:** two unequal small groups (e.g., 5 and 7), not yet counted.
- **SEE:** "Which looks like it might have more? Let's check."
- **BREAK:** pair one object from each group together, one at a time.
- **BUILD:** notice which group runs out of partners first (has objects "left over"
  belongs to the larger group).
- **TRANSFORM:** re-pair the same two groups in a different order — same group still has
  leftovers.
- **CHECK:** count both groups to confirm the pairing result.
- **Primary example:** 5 vs. 7 counters.
- **Second example:** 6 vs. 6 counters (no leftovers either way — introduces "equal").
- **Transfer example:** two groups of classroom objects the learner selects themselves.
- **Misconception:** re-counts both groups instead of using the pairing to decide. *Why:*
  hasn't yet trusted matching as sufficient evidence — reasonable at this stage, and
  counting to confirm is still encouraged, not corrected away.
- **Teacher response:** "You already paired them up — what did that tell you, before we
  even count?"
- **Check strategy:** alternate representation (count to confirm the pairing).
- **Mastery evidence:** uses pairing (not just counting) to correctly identify the
  larger of two groups at least twice.
- **Unlocks:** 0.1.5 (More/Less/Equal formalizes this comparison language).
- **Visual:** physical objects in two rows — no MTD component.
- **Format:** Both. **Presenter:** Recommended.

### 0.1.5 — More, Less, or Equal?
- **Type / Difficulty:** Discovery · Developing
- **Teaching goal:** name a comparison between two quantities using "more," "less," or
  "equal," backed by evidence (pairing or counting), not a guess.
- **Student question:** "Is this group more, less, or the same as that one?"
- **Prerequisites:** 0.1.4.
- **New idea:** the vocabulary "more / less / equal" attached to the pairing evidence
  from 0.1.4.
- **Reuses:** matching (0.1.4), counting (0.1.1).
- **Reasoning pattern(s):** Part/Whole.
- **Representation:** Object → Picture.
- **Vocabulary:** more, less (fewer), equal, the same as.
- **SETUP:** two groups are shown side by side.
- **SEE:** "Look at both groups. What's your first guess?"
- **BREAK:** pair the groups, or count each, to get evidence.
- **BUILD:** state the comparison word backed by the evidence just gathered.
- **TRANSFORM:** the same two groups, rearranged — comparison word stays the same.
- **CHECK:** a partner/teacher checks the pairing or count independently.
- **Primary example:** 4 vs. 6 objects.
- **Second example:** 5 vs. 5 objects.
- **Transfer example:** three groups at once — learner orders them using more/less/equal.
- **Misconception:** calls the visually larger *arrangement* "more" without pairing or
  counting. *Why:* judging by size/spread, same root cause as 0.1.3's misconception.
- **Teacher response:** "How could we prove it, instead of just looking?"
- **Check strategy:** alternate representation (pairing vs. counting should agree).
- **Mastery evidence:** correctly compares two groups using more/less/equal, with
  evidence, in at least 3 of 4 tries.
- **Unlocks:** 0.1.6 (proving equality formally).
- **Visual:** physical objects — no MTD component.
- **Format:** Both. **Presenter:** Optional.

### 0.1.6 — Proving Two Groups Are Equal
- **Type / Difficulty:** Strategy · Secure
- **Teaching goal:** "equal" is a claim that needs evidence — a learner should be able to
  *prove* two groups are equal, not just assert it.
- **Student question:** "How can you prove they are equal?"
- **Prerequisites:** 0.1.5.
- **New idea:** equality as a provable claim (pairing with zero leftovers, or matching
  counts).
- **Reuses:** matching (0.1.4), more/less/equal language (0.1.5).
- **Reasoning pattern(s):** Part/Whole, Equivalence (informal).
- **Representation:** Object → Picture.
- **Vocabulary:** prove, equal, exactly the same amount.
- **SETUP:** two groups that look different in arrangement but are secretly equal (e.g.,
  6 in a cluster and 6 in a row).
- **SEE:** "Someone says these are equal. How could we check?"
- **BREAK:** choose a method — pairing or counting both.
- **BUILD:** carry out the chosen method and record the result.
- **TRANSFORM:** the same two groups, rearranged again — the proof method still works.
- **CHECK:** try the *other* method (if pairing was used, count; if counting was used,
  pair) to see if it agrees.
- **Primary example:** 6 (cluster) vs. 6 (row).
- **Second example:** 8 (circle) vs. 8 (two rows of 4).
- **Transfer example:** a case designed to look unequal (very different footprints) but
  is exactly equal.
- **Misconception:** accepts "they look about the same" as proof. *Why:* has not yet
  internalized that a visual impression is not evidence.
- **Teacher response:** "'About the same' — can you show me for certain?"
- **Check strategy:** alternate representation (pairing and counting cross-check).
- **Mastery evidence:** independently chooses and correctly executes a proof method for
  at least two equal-quantity pairs.
- **Unlocks:** Unit 0.2 (proving equality is the direct precursor to proving two
  decompositions of the same whole are equivalent).
- **Visual:** physical objects — no MTD component.
- **Format:** Both. **Presenter:** Optional.

### 0.1.7 — Counting On From a Known Group
- **Type / Difficulty:** Strategy · Secure
- **Teaching goal:** if a group's size is already known (by subitizing or a prior count),
  counting can continue *from* that number rather than restarting from one.
- **Student question:** "Do we have to start over, or can we start from what we know?"
- **Prerequisites:** 0.1.1, 0.1.2.
- **New idea:** counting on — the efficiency insight that plants the seed for later
  addition strategies (Make 10, D1).
- **Reuses:** subitizing (0.1.2), cardinality (0.1.1).
- **Reasoning pattern(s):** Unitize.
- **Representation:** Object → Picture.
- **Vocabulary:** start from, count on.
- **SETUP:** a subitizable group of 4 is shown and instantly recognized; 3 more objects
  are added one at a time.
- **SEE:** "We already know this is 4. Do we need to count it again?"
- **BREAK:** separate what's already known (4) from what's new (the 3 added).
- **BUILD:** count on aloud: "4 ... 5, 6, 7" instead of "1, 2, 3, ... 7."
- **TRANSFORM:** the same total (7), reached two ways — recount from 1 vs. count on from
  4 — same value, different counting form.
- **CHECK:** recount fully from 1 to confirm counting-on gave the right total.
- **Primary example:** 4 known + 3 added.
- **Second example:** 5 known + 2 added.
- **Transfer example:** a group where the "known" part must be subitized on the spot,
  not pre-told.
- **Misconception:** recognizes 4 but still restarts counting from 1 anyway when more are
  added. *Why:* hasn't yet trusted that a known quantity can be a starting point rather
  than something that must always be re-verified from scratch.
- **Teacher response:** "You already told me that part is 4 — can we save time and start
  there?"
- **Check strategy:** alternate representation (full recount from 1 confirms the total).
- **Mastery evidence:** counts on from a known small quantity at least twice without
  prompting to restart from 1.
- **Unlocks:** 0.1.8; later, Unit 1.3's Make 10 bridging depends directly on comfort
  counting on from a benchmark.
- **Visual:** physical objects — no MTD component.
- **Format:** Both. **Presenter:** Recommended.

### 0.1.8 — Bigger Numbers, Same Idea
- **Type / Difficulty:** Strategy · Transfer
- **Teaching goal:** every idea in this unit (cardinality, subitizing, matching,
  more/less/equal, counting on) applies just as well to numbers up to about 12, not only
  to the small numbers first used to introduce them.
- **Student question:** "Does this still work with a bigger number?"
- **Prerequisites:** 0.1.1–0.1.7.
- **New idea:** none — this is a deliberate transfer/consolidation lesson, not a new
  concept, by design (a Foundation Mastery Check follows this lesson).
- **Reuses:** every prior lesson in this unit.
- **Reasoning pattern(s):** Unitize, Part/Whole.
- **Representation:** Object → Picture.
- **Vocabulary:** (review of the unit's vocabulary).
- **SETUP:** a group of 10–12 objects.
- **SEE:** "What do you already know how to find out about a group like this?"
- **BREAK:** the learner chooses their own method — count, subitize a known chunk and
  count on, or compare to another group.
- **BUILD:** carry out the chosen method(s).
- **TRANSFORM:** the same quantity, described using at least two of the unit's tools
  (e.g., "I subitized 5 and counted on 5 more to get 10, and I can also just count all
  of them one at a time — same answer either way").
- **CHECK:** a second method confirms the first.
- **Primary example:** a group of 10.
- **Second example:** a group of 12.
- **Transfer example:** comparing two groups of 10–12 using pairing.
- **Misconception:** reverts to only one tool (typically pure counting) even when a
  faster method is available and known. *Why:* the newer strategies (subitize + count
  on, pairing) are not yet automatic — expected at this stage, not a gap to remediate
  urgently.
- **Teacher response:** "That works — is there a way to do it that uses what you already
  know without starting all the way over?"
- **Check strategy:** alternate representation (a second method must agree).
- **Mastery evidence:** independently chooses and executes at least two different valid
  methods across the two examples, and both give the same, correct total.
- **Unlocks:** the Unit 0.1 Mastery Check (`MASTERY_CHECKS.md`), then Unit 0.2.
- **Visual:** physical objects — no MTD component.
- **Format:** Both. **Presenter:** Optional.
